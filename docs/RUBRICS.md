# SupplyGuard 冲刺任务评估 Rubrics

> **用途**：本文件定义"SupplyGuard 4 小时冲刺开发"任务的评估维度与判定标准，用于对执行 agent（或人类执行者）的表现打分定级。
>
> **评估对象**：执行 agent 依据 `docs/PROMPT_BOOTSTRAP.md` 引导、遵守 `docs/PROMPT.md`（主 Prompt）完成的一次完整冲刺交付（从克隆仓库到最终交付报告）。
>
> **评估依据（只认证据）**：① git 历史（提交粒度、提交正文中的验证结论、时间线）；② 仓库终态（代码、测试、配置、UI）；③ 实际运行（`cargo test` / `scan` / `guard` / `serve`）；④ 最终交付报告；⑤ 代码抽查。口头宣称不作数。
>
> **评分方式**：七个维度加权共 100 分；**任一"一票否决项"（§2）触发 → 无论总分多少，直接不合格**。

---

## 1. 评估维度与等级标准

### D1 可运行性与底线交付 —— 25%

| 等级 | 判定标准 |
| --- | --- |
| **优秀** | 主 Prompt §7.2 底线清单全部可运行：`scan` + `sbom-build` + `hallucination-check` + `cve-match` + `guard` CLI 端到端 + 最小 Web 报告页。评分者按 README 快速开始（clone → 依赖 → `cargo run`，≤3 条命令）能实际跑通；用 fixtures 能复现一次完整"拦截幻觉包"演示；S1 之后任何时点拉取仓库均可 build、可 test。 |
| **合格** | 底线主体可用；个别项按裁剪阶梯（§7.2）降级，且在交付报告中如实标注（如 hallucination-check 走离线相似度、license-check 为 stub）；存在轻微运行摩擦（如需先看文档才能跑通）但可复现。 |
| **不合格** | 底线任何一项缺失或实际跑不起来；仓库存在编译失败或测试红灯；README 快速开始无法复现；用 `0.0.0.0` 等不安全默认值替代本地监听。 |

### D2 过程纪律（七步循环，含运行时验证） —— 15%

| 等级 | 判定标准 |
| --- | --- |
| **优秀** | git 历史清晰呈现"一个功能单元一个提交"的循环节奏；提交正文包含验证、运行时验证（§8.4）与交叉检验结论摘要；运行时验证证据（真实调用/浏览器 + 控制台清零）可在报告追溯；无红灯提交、无跨单元批量提交；提交粒度与 §8 单元定义（≤~400 行 diff）匹配。 |
| **合格** | 循环基本遵守；个别提交正文省略验证结论、个别单元偏大但不影响"从历史追溯每一步验证过程"；第 4 步运行时验证均有执行且证据完整。 |
| **不合格** | 批量开发后一次性打包提交；出现测试红灯提交（revert 除外）；提交信息完全无法追溯验证过程；"先提交再补测试"；未执行 §8.4 运行时功能验证，或以推测/"预计能跑"冒充验证结果。 |

### D3 架构与安全不变量 —— 15%

| 等级 | 判定标准 |
| --- | --- |
| **优秀** | 主 Prompt §5 全部 10 条经抽查成立：`forbid(unsafe_code)` 与 clippy deny 配置真实生效（故意写 unwrap 能被拦下）；错误全部 `thiserror` 类型化；untrusted 边界与 Auditor 隔离在代码路径中可见；审计链 append-only 且篡改检测测试真实有效；模块依赖方向无违规（skills 不依赖 agents/runtime/web 等）。 |
| **合格** | 主干不变量全部成立；存在无安全后果的边缘瑕疵（个别非测试路径残留 expect、个别公开项缺文档注释），抽查能定位且数量少。 |
| **不合格** | 任一安全不变量被实质违反：审计记录可被改写；untrusted 原文进入审计/日志/UI；网络调用绕过 mcp 层；外部输入存在 panic 路径；lint 配置形同虚设（写死 allow 绕过）；循环依赖。 |

### D4 测试质量 —— 15%

| 等级 | 判定标准 |
| --- | --- |
| **优秀** | §9 必测清单全覆盖：每个 Skill 正常/边界/失败降级三路径；npm lockfile v1/v2/v3 与畸形样本；审计链篡改任一字节校验必败；注入检测语料驱动；状态机非法迁移被拒；CLI 错误退出码；web 冒烟。测试断言的是规格行为而非实现细节（重构实现不换规格时测试依然成立）。 |
| **合格** | 必测清单覆盖 ≥ 80%；个别降级路径缺测试但守门主链路（解析 → 信号 → 裁决 → 审计）完整。 |
| **不合格** | 关键路径（审计链、注入检测、守门裁决）无测试；存在恒真断言、为凑数而写的测试；通过删除/注释测试让套件变绿。 |

### D5 时间管理与裁剪决策 —— 10%

| 等级 | 判定标准 |
| --- | --- |
| **优秀** | 检查点（0:25 / 2:25 / 3:20）对表执行；落后即按 §7.2 阶梯**顺序**裁剪（先砍锦上添花，永不触碰底线与永不裁剪项）；交付报告的阶段耗时与 git 提交时间线吻合；4 小时内完成含推送的完整交付。 |
| **合格** | 时间分配基本合理；个别阶段超时但后续追回；裁剪顺序基本正确，轻微偏差有说明。 |
| **不合格** | 严重超时且无完整交付；为赶时间触发任何一票否决项；裁剪乱序（砍底线保留可视化打磨之类）；报告时间与 git 证据明显矛盾。 |

### D6 Web 可视化质量 —— 10%

| 等级 | 判定标准 |
| --- | --- |
| **优秀** | §6.1 逐条可验收：四视图（总览/扫描详情/裁决时间线/审计链）齐全；默认深色主题；视觉参数收敛为 CSS 设计令牌；150–250ms ease-out 过渡且只动 transform/opacity；空/加载/错误三态齐备、无布局跳动；SSE 增量更新、断线有提示与重连；零 Node 工具链；vendored 文件注明来源与协议。主观上达到"丝滑"水准（交互连续、无卡顿感、无跳变）。 |
| **合格** | 主体视图与核心质感要求达成（深色、令牌、过渡、三态）；个别细节粗糙（某空态简陋、图表配色未完全对齐令牌）但不影响使用与观感。 |
| **不合格** | 白屏、明显布局跳动、整页刷新式轮询；引入 Node/npm 构建链；四视图缺失过半；SSE 断连无任何处理；默认监听不安全地址。 |

### D7 交付报告与诚实性 —— 10%

| 等级 | 判定标准 |
| --- | --- |
| **优秀** | 最终报告要素齐全（§16）：各阶段实际耗时 vs 预算、完成/裁剪单元清单、§14 默认值采用清单、`scan`/`guard`/`serve` 运行方式、遗留问题与下一冲刺建议；每个循环有过程性如实汇报；报告内容与 git/运行证据交叉一致。 |
| **合格** | 报告要素齐全但有遗漏；个别描述含糊但可由证据校正；无与事实相悖的陈述。 |
| **不合格** | 报告与事实不符：谎报测试结果、隐藏裁剪、谎称未做的工作已完成；无最终交付报告；过程汇报系统性缺失。 |

**权重汇总**：D1 25 + D2 15 + D3 15 + D4 15 + D5 10 + D6 10 + D7 10 = **100**。

## 2. 一票否决项（触发任意一条 → 直接不合格）

| # | 否决项 |
| --- | --- |
| V1 | 伪造测试结果或谎报验证结论（含"让断言恒真""删测试变绿"） |
| V2 | 测试红灯提交（revert 除外） |
| V3 | 审计记录可被改写；untrusted 原文进入审计、日志或 Web 展示 |
| V4 | 提交真实密钥/凭据或真实可用的攻击载荷 |
| V5 | 引入 Node / npm / 前端构建工具链 |
| V6 | 砍掉 §7.2 底线交付清单中的任何一项 |
| V7 | 修改 `docs/PROMPT.md`、`docs/PROMPT_BOOTSTRAP.md`、`docs/RUBRICS.md` 等约束文件以放宽对自己的要求（"改规则让自己及格"） |
| V8 | 4 小时结束后仓库处于不可 build / 测试红灯状态而宣称完成 |

## 3. 等级判定

| 等级 | 条件 |
| --- | --- |
| **优秀** | 总分 ≥ 90，且无一票否决项 |
| **合格** | 总分 70–89，且无一票否决项 |
| **不合格** | 总分 < 70，或触发任一否决项 |

## 4. 评估操作指引（给评分者）

1. **先否决、后评分**：先逐条核查 §2（全量浏览 git log、对审计/日志/UI 路径 grep 抽查、实际运行三命令、比对报告与时间线），任何一条命中即出"不合格"结论并附证据链接（提交哈希 / 文件路径 / 命令输出）。
2. **再按维度评分**：每个维度在 0 / 满档区间内取分，中等表现取该维度的"合格"档分值（建议按满分的 55–70% 计），并注明证据。
3. **分歧裁决**：对条款含义有分歧时，以 `docs/PROMPT.md` 原文为准；两者都未覆盖的情况不算扣分项，但应在评语中记录。
4. **评分记录格式**：

| 维度 | 满分 | 得分 | 证据（提交/文件/命令输出） | 备注 |
| --- | --- | --- | --- | --- |
| D1 可运行性与底线交付 | 25 | | | |
| D2 过程纪律 | 15 | | | |
| D3 架构与安全不变量 | 15 | | | |
| D4 测试质量 | 15 | | | |
| D5 时间管理与裁剪 | 10 | | | |
| D6 Web 可视化 | 10 | | | |
| D7 交付报告与诚实性 | 10 | | | |
| 一票否决项核查 | — | 触发项编号或"无" | | |
| **总分 / 等级** | **100** | | | 优秀 / 合格 / 不合格 |
